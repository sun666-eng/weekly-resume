- 触发文本：第一行 `个人简历`，第二行 `姓名：张三`，后续有电话、邮箱、教育背景和经历。
- 实测：导入结果 `basics.name = "个人简历"`；独立 `姓名：阿依古丽·买买提` 也把标签一并放进姓名。只有带 `个人信息` 章节的对应样本正确提取“张三”。

- 证据：`fixtures.json` 的 `case-name-title-labeled.pdf`、`case-minority-label-isolated.pdf`。属于解析函数和真实 PDF 文本复现；本轮浏览器导入提交未完成。

### F03 · P2：中文文件导入后仍为 en-US，部分中国字段进入个人评价

- 结果：姓名、电话、邮箱提取成功；上述扩展字段及城市没有进入对应结构化字段，原文保存在 `summary.content`，**并未全部丢失**。所有中文导入样本的 `metadata.page.locale` 仍为 `en-US`；内置章节标题未按原中文标题落入数据，默认标题解析会使用英文。

### F04 · P2：Word 导出没有保留已显示的照片

- 9 个带照片模板、共 18 份应含照片的 DOCX，`word/media` 均为空；PDF 对照有照片。当前 `packages/docx/src/builder.ts` 没有图像渲染实现。
- 影响：明确选择照片的用户获得与预览不同的文件。应支持照片导出，或在 Word 下载前明确告知缺失；不要将照片设为所有用户必填。
- 这是此前已有的限制，本轮在全部带照片中文模板上再次确认。

### F05 · P2：当前中文字体不覆盖特定扩展汉字

- 压力样本含 `喆、珺、𠮷`；前两个保留，15 个模板中 `𠮷` 均未出现在 PDF 提取文本中，渲染原图也未正确显示。Word XML 保留原字符。
- 对实际 `Noto Sans SC/400.ttf` 使用 fontkit 检查：`hasGlyphForCodePoint(0x20bb7) = false`、glyph ID 0。当前字体回退组合未补足该字符，不能据常用字通过推断所有生僻姓名都受支持。
- 位置：`packages/pdf/src/hooks/use-register-fonts.ts:271` 的回退注册，以及 `apps/web/public/fonts/noto-sans-sc/400.ttf`；需增加覆盖所需扩展汉字的字体或缺字提示，并检查提取文本与视觉结果。
- 证据：各 `*-full.pdf`、`templates.json.pdfMissing`、`rendered/onyx-full-1.png`。

### F06 · P2：编辑器“在读”日期与 ATS 语法不一致

- 编辑器 helper 接受并生成 `2022.09 - 在读`，但 `parsePeriod` 返回 null，结构化 lint 产生 `UNPARSEABLE_PERIOD`。
- `2022年9月至2026年6月`、`2022.09～2026.06` 同样失败；前者的真实 PDF 还触发 `NO_DATES_FOUND`。有短横线的中文年月、点号、斜杠和“至今”通过；倒序产生 `REVERSED_PERIOD`，13 月被拒绝。
- 位置：`packages/schema/src/resume/cn-fields.ts:306` 与 `packages/resume/src/ats/period.ts:50`、`:64`。另一个较轻限制是编辑器 `parsePeriodRange` 对 `2022-09 - 2026-06` 返回 null，ATS 却能识别；原自由文本会保留，不能称为日期丢失。
- 建议：统一在读/至今及中文分隔符语法；用编辑器生成值作为跨模块回归输入。

### F07 · P2：ATS 把日期当电话，全角号码又会漏掉

- 同一份没有电话的简历，包含 `2022.09 - 2026.06` 时 `NO_PHONE` 通过；去掉日期后才失败。导入器在该样本上正确保持电话为空，两个入口语义不一致。
- `１３８００００００００` 全角号码在 ATS 和导入器中都没有识别为电话。
- 位置：`packages/resume/src/ats-pdf/analyze/contact.ts:12`、`:38` 的候选匹配/数字比例过滤没有排除日期。应先统一字符宽度，再排除日期范围，并保留国际号码兼容性。
- 证据：`case-no-phone-dot-dates.pdf`、`case-no-phone-no-dates.pdf`、`case-fullwidth-phone.pdf`。

### F08 · P2：姓名识别受页面位置影响，并存在误认城市

- 自家 `ditgar`、`gengar` 常规中文 PDF 中“林志远”可见且能提取，却触发 `NO_NAME_LINE`。双栏几何顺序使姓名不在前三条文本行。
- 独立 `阿依古丽·买买提` 的隔离样本失败，加 `姓名：` 后通过；没有姓名、只有标题与“杭州”的样本反而通过。另一个无姓名样本的中文院校/专业行也可能被宽松的多词姓名规则接受。
- 位置：`packages/resume/src/ats-pdf/analyze/contact.ts:119`；中文独立姓名限于前 3 行且 2–4 汉字，多词兜底则接受广泛 Unicode 字母。
- 建议：按页首区域和列结构选候选，优先标签，结合学校/地点/岗位排除，保留复合姓、间隔点及英文姓名。

### F09 · P2：并排的章节名与内容被合并，导致整组章节检查跳过

- `bronzor-sample.pdf` 的提取行是 `教育经历 江城理工大学 本科…`、`实习经历 星澜科技有限公司…`。

- 位置：`packages/resume/src/ats-pdf/analyze/sections.ts:80`、`:87`；`rules/sections.ts:24`。
- 建议：利用独立 span、字体和区域定位章节；界面保留跳过原因，不将此结果描述为全面合格。

### F10 · P3：中文默认流程仍有样例体验不一致
