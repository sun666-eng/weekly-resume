## 2. 改动内容

### 2.1 导入与字段复核

- 修复纯文本导入中一种已复现的内容错位：项目正文紧邻下一项目的日期时，`•实现 WAL 日志恢复。` 等句子被当作新项目标题，移入下一项目。
- 中文句末标点参与正文判断；无空格的中文圆点列表能被识别；破折号和星号仍要求后接空白，避免放宽为任意前缀。
- PDF/Word 导入发现疑似正文标题或未识别职位时，创建简历前显示复核确认。取消不会创建或跳转；继续导入保留解析结果，不猜测、不搬移字段。
- JSON 导入不追加此提示，保留精确回导体验；多岗位经历不误提示缺失职位。
- 工作经历列表缺失职位时显示“未填写职位”，避免“0 个岗位”让用户误以为内容已正确结构化。

限制：检查是启发式提示，不保证发现全部识别错误。修复验证了一个确定的导入机理，不能据此断定线上历史简历的所有错位都由这个机理产生。既有简历不批量改写。

### 2.2 保存、备份与重试

- 将保存状态独立为组件，手机也显示文字，不依赖悬停。
- 区分“正在保存”“已保存”“仅本机备份”“未保存”“处理冲突”。提示解释本机备份尚未保存到账号，其他设备不可见。
- 保存失败且无待处理冲突时提供“重试保存”，使用最新可见数据和原有乐观锁/冲突合并路径，不增加绕过版本检查的写接口。
- 连续点击重试只发出一次在途保存；锁定简历、有冲突、没有待保存编辑时不重试。
- 存储写入失败时不能把较旧的备份显示为最新编辑的备份。
- 接受服务器规范数据时清理过期的错误/备份标识和对应错误提示。测试先复现“服务器内容已接受但仍显示保存失败”，随后最小修复。

### 2.3 照片与手机布局

- 缩略图点击改为选择/更换；删除具有独立按钮，隐藏与删除分开。
- URL、大小、旋转、宽高比、边框、阴影收入默认折叠的高级设置；照片与显示方式保持可见。
- 加载失败时显示可操作的中文错误提示；加载成功后清除提示；照片隐藏时说明成品不显示。
- 选择文件前清空输入，允许重新选择同一个文件。
- 上传中删除、手动改 URL 都使旧上传任务失效，晚到的上传响应不能覆盖用户后续操作；没有旧照片时也可取消上传。
- 保留已有照片文件的撤销策略，不通过删除存储文件破坏撤销。
- 浏览器在 320px 长标题下复现顶部菜单与下载按钮重叠；调整手机横向空间分配，桌面仍保留原布局。修复后两按钮间距约 8px，页面宽度与滚动宽度均为 320px。

本批新增英文、简体中文、繁体中文文案 19 条；三个目录仅追加本批文案，没有把全量提取混入改动。

### 2.4 备份演练工具

新增 `tooling/verify-backup-restore.sh`。输入备份目录，要求 `database.dump` 和 `uploads.tar.gz`。

- 只读挂载备份，检查压缩文件可读性。
- 使用本机已有的 `postgres:17-alpine`，不下载镜像；不连接业务网络、不暴露端口。
- 新建临时 PostgreSQL 容器，网络隔离，256MiB 内存与 256MiB 临时数据目录限制，100MiB dump 输入上限。
- 实际执行 pg_restore，输出用户/简历/版本计数，清理仅限本次创建的精确容器 ID。
- 备份更新频率、照片引用完整性、应用版本兼容性需要另外验证；脚本不把这些项目算作已完成。

本机 Docker 引擎未启动，当前服务器 SSH 认证未成功，因此本次仅完成脚本语法及缺失参数保护验证。下一步应在有权限的测试环境中使用真实备份执行恢复演练，不在生产数据库中试恢复。

| 场景 | 验证方式 | 结果/边界 |
