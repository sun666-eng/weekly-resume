## 服务器上的下一步（只读核验优先）

1. 确认真实部署目录、Compose 项目名、应用服务名、当前镜像 ID、数据库卷和照片存储卷。
2. 在服务器检查现有环境文件的配置有效性，仅输出通过/失败，不输出密钥。复用已有 AUTH_SECRET、ENCRYPTION_SECRET 和数据库密码；更换这些值必须有独立迁移方案。
3. 用对应版本的配置预检脚本检查现有生产配置，确认 HTTPS APP_URL、真实 SMTP、限流开启、不安全地址和 OAuth 开关关闭。公网兼容 API 中转站通常不需要开启不安全地址开关；实际兼容性仍须验证。
4. 对实际部署编排执行 `docker compose ... config --quiet`。不要仅凭本地示例编排覆盖正在使用的部署方式。
5. 确认数据库与上传文件备份可恢复，并保存当前镜像及回滚命令。应用启动会执行数据库迁移，不能把旧镜像回滚等同于数据库可回滚。
