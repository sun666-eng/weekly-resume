# 中文简历编辑器左侧填写区优化计划

> 交付对象：实施本计划的开发者（Grok）。本文件是实施方案，尚未修改产品代码。

## 1. 目标与边界

让用户从空白简历开始，就能按国内求职习惯依次填写基本信息、教育、技能、实习、工作、项目等内容，并且输入的数据在实时预览、模板切换、保存、导入导出后仍然一致。参考[卡码简历编辑器](https://jianli.kamacoder.com/)的**字段和填写顺序**，保留本项目现有的左侧栏外观、章节折叠、添加/编辑按钮、弹窗、拖拽排序、右侧模板设置与整体交互方式；不复制参考网站的 UI 或示例简历内容。

此任务只针对**中文简历的新建和编辑体验**。英文简历和既有简历保留原有数据与可编辑能力；不因切换语言或模板丢失字段。先解决填写与数据闭环，再做非必要的视觉细节。

## 2. 核查依据与现状

- 用户截图：现有“基本信息”依次为姓名、标题、电子邮件、电话、位置、网站、自定义字段；参考图的基本信息是姓名、电话、邮箱、性别、年龄、个人博客、Github、求职意向、政治面貌、住址，头像在该表单顶部。参考图还展示教育背景、校园经历、专业技能、实习经历、工作经历、项目经历、获奖经历、证书信息、个人评价、科研成果等栏目。
- 2026-09-25 实际查看参考网站的编辑器：教育包含学校名称、学校层级、专业、学位、GPA、在校时间、主修课程；工作包含公司、职位、部门、地点、工作类型、时间、内容；实习包含公司、职位、地点、时间、内容；项目包含名称、角色、时间、描述。技能、获奖、个人评价、科研、校园、证书采用文本/Markdown 编辑。以上仅作为字段语义参考，**不要求复制其保存按钮或 Markdown 编辑器**。
- 本项目的基本信息见 `apps/web/src/routes/builder/$resumeId/-sidebar/left/sections/basics.tsx`，头像已有独立的 `picture.tsx`，故应保留头像入口，必要时在基本信息顶部提供同一入口的跳转提示，不能再造一套照片数据。
- 基础数据定义见 `packages/schema/src/resume/data.ts` 的 `basicsSchema`，默认值见 `packages/schema/src/resume/default.ts`。当前字段只有 `name/headline/email/phone/location/website/customFields`；新增基本字段不能只改表单，否则保存或导出时会消失。
- 左栏章节列表见 `apps/web/src/libs/resume/section.tsx`；当前有 `summary`、`experience`、`education`、`projects`、`skills`、`awards`、`certifications`、`publications`、`volunteer` 等。`customSections` 可复用 `experience`、`summary` 等类型，见 `packages/schema/src/resume/data.ts`，适合承载独立的“实习经历”“校园经历”等栏目。
- 当前教育、工作、项目等条目表单在 `apps/web/src/dialogs/resume/sections/`。PDF 页眉从 `packages/pdf/src/templates/shared/template-base.tsx` 读取基础字段，DOCX 从 `packages/docx/src/builder.ts` 读取。输入字段、预览和导出必须同时打通。
- 当前 `defaultResumeData.metadata.page.locale` 为 `en-US`，中文样例 `packages/schema/src/resume/sample-zh-cn.ts` 已设 `zh-CN`。新建空白简历的中文默认体验需要单独处理，不能直接改写所有旧简历的默认布局。

## 3. 基本信息：字段对照与落地

中文模式左栏建议顺序：**姓名 → 电话 → 邮箱 → 性别 → 年龄 → 个人博客 → GitHub → 求职意向 → 政治面貌 → 住址 → 更多信息**。在窄左栏中沿用当前单列排布；参考站的双列布局不移植。

| 参考字段 | 本项目现状 | 实施要求 |
| --- | --- | --- |
| 头像 | 已有独立“照片”章节 | 保留现有上传、裁剪、隐藏和删除功能；基本信息顶部可加文案或定位入口，不新增图片存储。头像可选。 |
| 姓名 | `basics.name` | 放首位；中文占位示例。 |
| 电话 | `basics.phone` | 放第二位；支持中国手机号和其他合法联系电话，不强制只允许 11 位。 |
| 邮箱 | `basics.email` | 放第三位；空值允许暂存，填写后做格式校验。 |
| 性别 | 无 | 新增可选字段；选项含男、女、其他/不公开，空值不显示。 |
| 年龄 | 无 | 新增可选年龄字段，接受合理整数；空值不显示。不要根据空白生日虚构年龄。 |
| 个人博客 | 仅有泛化 `website` | 新增或明确映射个人博客 URL；保留旧 `website` 值及编辑入口，防止旧链接消失。 |
| GitHub | 可通过 `profiles` 间接填写 | 基本信息提供直接填写入口；与已有 GitHub profile 定义单一数据来源或明确同步规则，避免 PDF 重复两次。 |
| 求职意向 | `basics.headline`（标题） | 中文标签改为“求职意向”，沿用 `headline` 存储与模板页眉呈现。已有标题内容不迁移丢失。 |
| 政治面貌 | 无 | 新增可选字段，支持常见选项和“其他”文本；空值不显示。 |
| 住址 | `location`（位置） | 中文标签先可使用“现居地/城市”；若提供详细住址则新增独立可选字段，不能把城市与详细地址合并覆盖。 |
| 更多信息 | `website/customFields/profiles` | 原有网站和自定义字段保留在基本信息后部或现有章节内；仅调整优先级。 |

实施时在 schema 中定义新增字段的默认空值与兼容解析，更新空白数据、示例数据、表单状态同步、API 写入/读取与导入器。姓名、电话、邮箱应在 UI 提示为核心信息；**不要用全表单必填校验阻断逐字自动保存**。可在导出前给出缺项提示。性别、年龄、政治面貌、详细住址属于自愿填写的信息，用户留空时预览/PDF/DOCX 不显示占位符，也不自动公开。URL 仅允许安全的 `http/https` 链接，按现有 URL 控件规则验证。

## 4. 章节与条目表单对照

| 参考站栏目/字段 | 本项目已有能力与差异 | 建议实施方式 |
| --- | --- | --- |
| 教育背景：学校、学校层级、专业、学位、GPA、在校时间、主修课程 | `education` 已有学校、专业(`area`)、学位(`degree`)、成绩(`grade`)、期间(`period`)、地点、描述；时间为单字符串，学校层级和主修课程无专用标签 | 中文标签和字段顺序按参考调整；`grade` 显示为 GPA/成绩；主修课程先用 `description` 富文本并给结构化提示。学校层级可选新增字段，若新增须贯通渲染与导出。保留自由输入期间，但提供起止时间辅助填写，支持“至今/在读”。 |
| 工作经历：公司、职位、部门、地点、工作类型、时间、内容 | `experience` 已有公司、职位、地点、期间、描述、多岗位；缺部门和工作类型 | 调整中文标签/顺序和描述提示。部门、工作类型作为可选字段新增或用兼容的扩展字段；不可覆盖 `roles` 多岗位数据。 |
| 实习经历：公司、职位、地点、时间、内容 | 当前没有独立实习章节，但 `customSections(type=experience)` 可复用工作条目 | 中文新建空白简历预置标题为“实习经历”的 experience 型自定义章节；复用现有条目弹窗及增删排序，区分正式工作。旧简历不自动挪动经历。 |
| 项目经历：名称、角色、时间、描述 | `projects` 已有名称、期间、网址、描述；缺独立角色 | 增加可选“担任角色”，保留网址与富文本描述；中文描述提示按“项目背景/本人职责/技术或方法/结果”组织，不预填虚构业绩。 |
| 专业技能：技能内容 | 当前 `skills` 为多条技能、熟练度与关键词 | 保留结构化条目和现有按钮。优化中文字段标签与示例，使用户能直接写技能点；不强迫改成参考站的单个 Markdown 文本框。 |
| 校园经历：学生工作、社团活动等 | 当前 `volunteer` 与自定义章节可承载，缺明显入口 | 中文空白简历预置“校园经历”自定义章节；优先采用能表示组织、职务、期间、内容的 `experience` 型条目。志愿经历继续保留原章节。 |
| 获奖经历 | `awards` 已有奖项、颁发方、日期、描述 | 仅优化中文标签、示例和条目顺序；继续保留结构化输入。 |
| 证书信息 | `certifications` 已有名称、颁发机构、日期、描述 | 优化中文标签与示例；与获奖分开，不把证书塞到获奖文本里。 |
| 个人评价 | `summary` 富文本 | 中文标题与说明改为“个人评价”，保留当前富文本编辑器及原内容。 |
| 科研成果：论文、专利、研究报告 | `publications` 已有论文/出版物，缺对专利与报告的清晰指引 | 中文标题可改为“科研成果”；先用现有 publication 条目+描述/链接承载，给出“论文/专利/研究报告”示例；只有确有结构化展示需求时才新增成果类型字段。 |
| 语言、兴趣、社交资料、志愿经历、推荐人等 | 本项目已有独立章节，参考站主栏目未突出 | 保留数据与入口，放在中文常用栏目之后或“更多章节”；不删除、不自动隐藏旧简历已有内容。 |

中文新建简历的推荐填写顺序：**照片/基本信息、教育背景、专业技能、实习经历、工作经历、项目经历、校园经历、获奖经历、证书信息、个人评价、科研成果、更多章节**。这只是左侧填写顺序；PDF 页面顺序仍由现有布局设置控制。空章节应以易理解的“添加…”提示出现，但未填写的章节不能在 PDF 中留下空标题。

## 5. 实施步骤

### P0：空白中文简历与基本信息闭环

1. 识别中文创建场景：新建中文简历使用中文编辑字段顺序与中文默认章节/页面语言；英文创建与旧数据保持原样。选择依据应明确为当前界面语言或用户在创建时选择的简历语言，**不要仅凭浏览器时区或姓名猜测**。现有创建按钮和流程不改。
2. 扩展 `basicsSchema`、默认数据和兼容解析；为旧简历缺少的新字段填空默认值。梳理 `website`/`profiles` 与个人博客/GitHub 的单一来源和去重规则。调整 `basics.tsx` 的中文字段、顺序、输入类型和校验。图片仍通过原 `picture.tsx`。
3. 打通实时预览、PDF 全模板页眉、无障碍文本、DOCX、公开简历与 JSON 导入/导出。新增可选字段应按“有值才显示”呈现；版面紧凑，过长链接不撑破 A4。模板切换不修改表单数据。
4. 确认新建保存、刷新、再次编辑后字段完整；空值、已有 `headline/website/profiles` 与旧格式导入均不丢失。

### P1：中文章节和条目填写

1. 调整中文常用章节的名称、顺序与说明，保留既有章节菜单、增删按钮、弹窗和拖拽。通过 `customSections` 给中文新建简历提供独立实习与校园入口；新增章节必须进入布局 `metadata.layout.pages`，并可在所有模板中预览、导出。
2. 教育、工作、项目弹窗按第 4 节调整字段标签/顺序和占位提示；只为实际无法用已有字段表达的内容增加 schema 字段。若把时间拆成开始/结束 UI，继续兼容旧 `period` 字符串；不得因解析失败清空旧值。
3. 奖项、证书、科研、技能、个人评价使用现有结构化/富文本机制优化中文说明。空表单不显示演示内容；输入描述中的示例文案不能保存为用户事实。

### P2：回归与细节

1. 检查中文与英文界面、手机与桌面、空白与旧简历、图片有无、长中文文本及多页 PDF。检查 11 个参考栏目都可以找到对应填写入口。
2. 对 schema 默认/兼容、表单自动保存、章节布局、模板切换、PDF/DOCX/JSON、导入后再编辑写有意义的回归测试；执行仓库现有 typecheck、相关单测和构建。
3. 整理 `zh-CN` 翻译目录与字段文案，避免只在代码里硬编码中文导致英文模式出现中文标签。

## 6. 重点代码入口

- 左栏与章节：`apps/web/src/routes/builder/$resumeId/-sidebar/left/index.tsx`、`sections/basics.tsx`、`sections/picture.tsx`、`apps/web/src/libs/resume/section.tsx`。

## 7. 验收清单

- [ ] 中文用户创建**空白**简历后，左栏立即显示上述基本字段与常用章节；无需先导入或选择样例。
- [ ] 姓名、电话、邮箱、性别、年龄、个人博客、GitHub、求职意向、政治面貌、住址能录入；可选字段留空不阻断保存、不出现在成品中。
- [ ] 教育、技能、实习、工作、项目、校园、获奖、证书、个人评价、科研都有明确填写路径，新增条目后左栏与预览同步。
- [ ] 刷新、切换模板、导出 PDF/DOCX/JSON、重新导入后数据不丢失或重复；中文文字、链接、头像与多页布局正常。
- [ ] 旧简历的标题、网站、社交链接、工作经历及自定义章节仍可编辑；英文简历的原字段标签与功能不回退。
- [ ] 现有按钮、弹窗、侧栏视觉体系与右侧模板操作保持原有用法；无空章节标题、示例假数据或重复联系方式出现在导出文件中。

## 8. 实施约束

本计划关注“填写内容适配中国简历”，不要求照搬卡码简历的界面、账号体系、保存方式、模板或水印。请按 P0→P1→P2 实施，每个阶段完成后按第 7 节验证；若某字段需新增数据结构，必须连同读取、保存、预览、导出和旧数据兼容一并完成，不能留下只有编辑框、成品不显示的半成品。
