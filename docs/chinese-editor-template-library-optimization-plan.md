# 中文简历编辑器与模板库优化计划

日期：2026-09-26。状态：P0、P1、P2 已完成；P3 真实数据库核心链路已完成，扩展覆盖矩阵和用户本地验收待执行。保留现有按钮、输入框及整体界面风格。实施证据见 `editor-localization-implementation-report.md`、`template-reference-mapping.md` 和 `template-library-acceptance-report.md`。

## 一、当前问题与代码依据

1. 中文化已有字段与章节顺序改动，但不完整。`packages/schema/src/resume/blank-zh-cn.ts` 的新建布局仍含 references、interests、volunteer、profiles、languages；`apps/web/src/libs/resume/sidebar-order.ts` 的中文顺序也保留这些章节，仅按 hidden 过滤，未按中国求职场景收敛默认入口。
2. “推荐人”并非所有中文简历绝对不能用，但不适合中国大陆常规求职的默认编辑栏。不能用直接删 schema 或删除旧简历内容解决。
3. `packages/schema/src/templates.ts` 登记 15 个渲染模板 ID。`apps/web/src/dialogs/resume/template/gallery.tsx` 平铺模板卡片；当前没有“风格分类 → 多个具体版式”的浏览层级。
4. 首页通过 `features/homepage/template-shelf.tsx` 与 labels 工具挑选模板；应维持精选四个代表入口，与全量模板库解耦。
5. 实施前，用户提供的 ③—⑬ 共 11 张参考尚未逐一核对实际落地版式；15 个模板 ID 本身不能证明 11 张参考已经准确实现。现已按 P2 的映射证据逐张完成核对。
6. “模板简单”应区分排版质量和装饰数量：应改善层级、密度、对齐、分页和差异性，不能只增加背景色、图标或把换色算成新模板。

## 二、目标体验

- 从零创建中文简历：先选“应届生 / 有工作经验 / 科研学术”，也可跳过使用通用配置。选择可更改且不清空已填内容。
- 默认左栏展示常用章节；罕用章节通过“添加章节”进入。
- 语言切换只改变界面文案，不自动改简历内容、隐藏状态或章节顺序。已有 metadata.page.locale 是文档语言，不能成为破坏性迁移触发器。
- 首页保持四个代表模板，另有“查看全部模板”。点击分类入口进入对应分类，点击“使用此模板”才选择具体模板。
- 模板库支持分类筛选；例如“简约”是类别，“简约·经典单栏”“简约·紧凑技术”“简约·双栏概览”是不同版式。
- 切换模板只改变版式，不带入林志远示例内容、不改用户姓名照片、不丢章节。

## 三、编辑器默认章节

### 3.1 分层

| 层级 | 章节 | 行为 |
|---|---|---|
| 固定基础 | 基本信息（含可选照片） | 默认可见，照片可不填；不默认生成头像 |
| 常用 | 教育背景、专业技能、工作经历、项目经历 | 根据求职场景排序和默认展开 |
| 场景常用 | 实习经历、校园经历、获奖经历、证书信息、个人评价、科研成果 | 在应届生/工作/科研配置中按需启用 |
| 扩展 | 语言能力、作品与链接、志愿服务、兴趣爱好、自定义章节 | 通过“添加章节”使用 |
| 更多/国际求职 | 推荐人 | 中文新建不默认出现，仍可主动添加 |

应届生建议顺序：基本信息 → 教育背景 → 专业技能 → 实习经历 → 项目经历 → 校园经历 → 获奖与证书 → 个人评价。

有工作经验：基本信息 → 职业概述 → 工作经历 → 项目经历 → 专业技能 → 教育背景 → 证书。

科研：基本信息 → 教育背景 → 研究经历 → 科研成果 → 专业技能 → 荣誉奖励。研究经历先评估复用自定义 experience 章节，避免新增重复数据模型。

以上是新建预设。已填章节必须可访问；空章节不出现在成品，不表示数据库要删除该章节。

### 3.2 基本信息与填写方式

- 首屏：姓名、电话、邮箱、求职意向、现居城市，照片入口。
- “更多个人信息”：性别、年龄/出生年月、政治面貌、详细住址；全部选填，未填不输出，“不公开”不输出。
- “作品与链接”：博客、GitHub、作品集，避免基础信息与 profiles 重复输出同一链接；对旧数据只去重展示，不静默删除来源字段。
- 中文标签采用“求职意向”“现居城市”等明确术语，减少“标题”“位置”歧义。
- 每个经历条目显示名称、职位/角色、时间摘要；富文本说明直接面向职责和成果，示例只作 placeholder，不能保存成用户事实。
- 专业技能保持分类＋具体技能；“整理技能分组”入口移到章节标题附近或章节菜单，避免长列表底部难发现。新增入口调用同一功能，不复制另一套逻辑。
- 统一输入提交规则：输入法确认不误提交；直接点保存不丢末项；取消不写入；键盘可完成编辑。

### 3.3 章节管理与旧数据

推荐实现一个共享“编辑器章节可见性”计算函数，供桌面侧栏、图标导航、移动端和添加章节菜单共用。

必须区分：

1. 编辑入口是否默认展示；
2. 简历成品是否隐藏该章节；
3. 数据是否存在。

不要直接把“推荐人不默认显示”实现为覆盖所有旧简历的 `hidden=true`。含推荐人数据的旧简历继续显示编辑入口，并标注为已有扩展章节。原本隐藏的内容通过已有恢复入口可找回。

新建中文预设应默认不在活动章节中启用推荐人。若需要保存编辑模式/显式启用项，可增加可选、版本化配置；缺失配置按兼容规则计算，先检查现有偏好模型能否复用。不得先做数据库全量迁移。

## 四、模板库结构

### 4.1 分类与第一阶段候选数量

| 风格分类 | 候选具体版式 | 数量目标 |
|---|---|---|
| 简约 | 经典单栏、紧凑技术、留白通用、双栏概览 | 4 |
| 商务 | 标准职场、行政运营、金融咨询 | 3 |
| 校园 | 校招综合、实习项目、竞赛实践 | 3 |
| 学术 | 科研成果、技术开源 | 2 |
| 设计感 | 青蓝分区、几何标题、柔和侧栏 | 3 |

第一阶段目标是约 15 个经过审核的不同版式，不是立即在现有 15 个之外新增 15 个。先审计现有模板和 11 张参考，复用合适版式，补齐缺口。后续有需求和质量证据再扩到 20—24 个。

每个模板有一个主分类，可附适用场景标签；每张卡只展示最多三个有用标签，例如“单栏 / 可选照片 / 信息紧凑”，不要堆叠“专业、通用、极简”等重复词。

### 4.2 首页与模板库

- 首页延续四个精选模板，建议分别代表简约、商务、校园、设计感。学术分类仍在完整库可见。
- 首页代表模板仍是实际可用的具体版式，不把分类名称伪装成模板 ID。
- 卡片提供“使用此模板”和“查看同类”，后者带分类筛选进入模板库。
- 库顶部：全部、简约、商务、校园、学术、设计感；附搜索与单/双栏、照片、密度筛选。手机端分类横向滚动，筛选可收起。
- 模板预览先显示大图，再提供“用我的内容预览”；登录用户在编辑器切换前能预览当前内容。
- 无结果提示清除筛选，不显示空白网格。

### 4.3 模板元数据

保留稳定 renderer ID；新增展示用目录元数据，建议字段：

`id / categoryId / displayName / description / layoutType / density / photoSupport / locales / useCases / homepageFeatured / previewAssets / referenceId`。

不得用中文展示名作为存储主键。重命名和重新分类不改变旧简历引用。

颜色、字体等皮肤变化作为同模板选项；有实质网格、页眉、分区结构差异才作为独立版式。复用 renderer 的独立预设必须有稳定 preset ID，并明确可持久化的样式白名单与撤销策略；不能暗中覆盖用户整份 metadata。

### 4.4 参考图 ③—⑬ 的落地审查

建立 11 行对照清单：参考编号、主要结构、相似组、拟主分类、目标模板 ID、已实现/待实现、截图证据。

- ③：蓝色小图标、紧凑校园技术；④：蓝线单栏、照片、综合校招。
- ⑤⑥：学术/技术型紧凑版面，区别留白、页眉和项目层级，避免只换色。
- ⑦⑪⑬：带侧边竖线和色带标题，属于相近结构，需要明确差异或作为同系列预设。
- ⑧：圆角标题与柔和背景；⑨：黑白线性图标、宽松分区。
- ⑩：深色标题与技术/运营版面；⑫：几何色块与规则分区。

用户希望收录 ③—⑬，应保留每张的版式对应关系；相似的可以归同系列，但不能未经说明直接省略。示例统一使用林志远的虚构示例资料，照片用已获授权的示例资产；不复用参考里的真实联系方式或把他人照片标作林志远。模板是可编辑组件，不是截图背景。

## 五、质量标准

1. 同一套内容横向比较，检验结构差异；另用应届生、社招、学术内容检查适配，不用不同文字掩盖模板相似。
2. 中文字重、正文大小和行距舒适，标题、公司/项目、职责正文层级清晰；不为一页强制缩成小字。
3. 短内容不空出半页头部，长内容能自然多页；分类标题与首行尽量同行分页，长条目允许合理跨页。
4. 无照片时布局自然收拢；有照片时不遮挡联系方式。
5. 所有适用字段可渲染：新增中文字段、实习、校园、自定义章节、技能分组不得掉出模板。
6. 模板缩略图必须由实际 renderer 生成；示例预览、实际预览和 PDF 使用同一套规则。
7. PDF 导出做文字与图像检查；DOCX 保证语义层级和内容，若无法完全复现 PDF 的装饰布局要在功能说明中明确，不能承诺像素一致。
8. “ATS 友好”标签需有文本顺序、字段可提取性测试，不等同于保证所有招聘系统识别或提高录用率。

## 六、实施批次与检查点

### P0：中文默认编辑流程

修改候选：blank-zh-cn、sidebar-order、section-recovery、左栏组件及移动端消费者。

交付：默认章节策略、旧数据兼容规则、技能整理入口前移、新建场景预设。验收：中文从零创建不默认显示推荐人；旧简历推荐人内容仍可访问和导出；切语言不改数据；桌面手机入口一致。

### P1：模板目录与首页解耦

修改候选：template labels/data/gallery、homepage template-shelf、template-assets 与适当的共享目录模块。

交付：分类筛选、同类多个具体模板、首页固定精选四个、清晰标签。先用当前模板完成分类，不急于制作新模板。

验收：分类计数和筛选正确；首页代表跳转分类正确；旧模板 ID 不变；当前模板筛选后仍可识别；应用与撤销保留用户数据。

### P2：版式升级与参考图补齐

先做好简约类三种明显不同的版式，用统一长短样例出 PDF 供用户选择，再扩到其他分类。每批 2—3 个模板，避免一次改全部 renderer。

交付：参考映射表、模板设计规范、真实缩略图、A4 短/长/无照片/多字段样例。不要同时改解析、认证或保存机制。

执行状态（2026-09-27）：已完成。③—⑬共 11 张原图已逐张映射并记录差异；15 个真实 renderer 缩略图已进入模板库；scizor、rhyhorn、ditto 的统一短/长/无照片 PDF 样例及 15 模板技能完整性测试通过。纯文本联系方式问题作为独立小修复完成，不改变认证或保存机制。

### P3：全链路回归与发布准备

串联：新建 → 填写 → 保存 → 刷新 → 切模板 → PDF/DOCX/Markdown/JSON → JSON 回导 → 公开预览。

核心链路执行状态（2026-09-27）：已在当前源码构建的本地生产镜像、真实 PostgreSQL 和真实登录会话中通过。保存刷新、显式模板应用及持久化、四格式导出、JSON 回导和匿名公开预览均成功；最终公开地址为 `http://127.0.0.1:3200/editor.review/0927-0506-80`。PDF 完成渲染检查，DOCX 完成 OOXML 与核心字段检查；当前内置依赖缺少 LibreOffice，DOCX 视觉渲染未完成。

覆盖 zh-CN、zh-TW、英文；390px 手机；无照片；3 页以上；空章节；隐藏个人字段；旧数据；双标签并发；断网恢复；模板切换撤销。

扩展覆盖状态：P2 已独立覆盖 390px、无照片、3 页长样例、旧数据兼容和模板切换撤销；zh-TW/英文端到端、双标签并发、断网恢复及多条件组合仍待回归，不计入本次核心链路通过结论。

先审查代码和自动化，再跑独立本地生产镜像与真实浏览器。用户本地确认后才安排提交、推送、服务器部署；本计划不授权立即上线。

## 七、必须通过的对抗性用例

- 含推荐人联系方式的旧简历打开后不丢字段、不意外公开；中文新建不出现该空入口。
- 切换界面语言十次，序列化简历内容不变。
- 三组 18 项技能在所有模板和导出中不丢失、不重复，隐藏组不泄露。
- 简约类互切仅版式变化；普通文本、姓名、头像、联系方式和章节 ID 保持不变。
- 旧模板更名或改分类后可继续打开、预览、导出。
- 同名模板与搜索空结果不会选错实际 ID；首页展示数量不随新增模板无意增长。
- 当前正在输入时打开模板预览不丢草稿；取消预览不写入。
- 保存后刷新、退出重登，场景选择和已启用章节仍正确。
- 長标题、中文英文混排、括号内标点、不同字重、缺字体和离线字体均有明确结果。
