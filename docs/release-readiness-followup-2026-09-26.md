### 发布配置预检

新增：

- `tooling/production-config-checks.ts`：针对仓库 `compose.production.yml` 的纯配置检查。
- `tooling/release-preflight.mts`：Node 24 直接运行，仅读取明确指定文件，不连接服务、不发送邮件、不调用模型。
- `tooling/release-preflight.test.ts`：18 个测试覆盖有效配置、占位值、错误 TLS 模式、测试开关、数据库 URL 特殊字符及结果脱敏。
- 根脚本 `release:preflight`。

检查内容：正式 HTTPS 根地址、独立且非占位的密钥、数据库 URL 可安全插入的字符、端口/持久目录与 Compose 的一致性、禁用不安全测试开关、邮件配置完整性与 465/587 的 TLS 模式、本地邮件捕获服务误用。

运行方式（环境文件路径相对仓库根目录，也可提供绝对路径）：

```sh
node tooling/release-preflight.mts --env .env.production
# 或
pnpm release:preflight --env .env.production
```

退出码：0 为这些配置检查通过，1 为检查不通过，2 为文件/参数/执行错误。输出仅包含固定检查名称与提示，不输出密码、密钥或完整环境变量。

实际命令验证：合规虚构配置退出 0；`deploy.env.example` 的占位配置被拒绝；`.env.nightly` 的 HTTP/邮件捕获/测试开关被拒绝；缺失文件退出 2。首次使用 `pnpm --filter ... exec` 的包装会统一失败码为 1，现已改为直接 Node 命令，最终退出码已核验。

**边界：配置检查通过不等于真实 SMTP 已投递、不等于模型调用成功，也不等于生产网络可达。** 不应为了让预检变绿而直接更换运行中数据库密码或加密密钥；已有部署的密钥变更应按独立迁移方案处理。

## 发布前的实际执行顺序

1. 在服务器或受控环境对**实际** `.env.production` 运行预检。当前本地没有这个文件，不以示例配置代替它。
2. 核对发布范围，包含未跟踪的新源码、同源字体、许可证和迁移；排除测试账号、浏览器状态、环境文件和临时脚本。保留现有上线镜像标识及部署配置。
3. 备份生产 PostgreSQL 和 `/app/data`；备份必须能恢复。若包含迁移，确认向后兼容性；不能把切换旧镜像当作数据库回滚。
4. 构建/交付镜像后替换应用容器，保持现有数据卷。严禁使用 `down -v` 作为发布步骤。
5. 等应用健康，核对迁移日志及实际 HTTPS 域名、代理和客户端 IP 转发。
6. 用受控账号实测注册/登录、验证邮件与密码重置真实收信、创建/导入简历、保存刷新、切换模板和导出；有发布分享时检查匿名访问及跨账号隔离。
7. 若开放 Agent，使用正式模型配置做一次批准/拒绝/撤销与保存验收；本地 mock LLM 的旧验收不能替代它。
8. 上线后检查健康、关键错误日志、真实浏览器和移动端。若失败，按已准备的应用/数据库回滚方案处理。
