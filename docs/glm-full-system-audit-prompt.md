# Weekly Resume 全量系统测试与审计提示词（只测试，不修复）

你是本项目的高级测试负责人和发布审查人。请在 `D:\MyProjects\Weekly  Resume\weekly-resume-release` 对 Weekly Resume 做一次基于证据的全量系统测试与审计。目标是找出会影响真实用户的缺陷、准确定位根因、收集可复核证据，并交付测试报告。**本轮只测试和分析，不修复代码。测试完成后由另一位工程师根据报告统一修复。**

## 最高优先级执行约束

- 禁止修改任何源码、测试、配置、数据库结构、迁移、依赖、锁文件、Docker 文件、环境文件和 Git 文件。
- 禁止运行会写入项目源码或配置的格式化、代码生成、迁移、自动修复和升级命令。
- 禁止为了让测试通过而修改断言、快照、fixture 或测试数据。
- 禁止 `git reset`、`git checkout`、`git clean`、删除文件、覆盖文件、提交、推送、部署。
- 允许写入的内容只有：`docs/glm-full-system-audit-report.md`、`docs/glm-full-system-audit-handoff.md` 和 `docs/glm-full-system-audit-evidence/` 下的截图、日志摘要、JSON 结果。若这些报告已存在，先保留旧文件并写入带时间戳的新文件，不覆盖旧报告。
- 如果发现需要修复的代码，只记录文件、行号、复现、根因和建议方案，不要动代码。
- 如果某个工具会自动生成源码、缓存或修改 lockfile，停止该命令并在报告中记录“未执行，原因是会产生写入”。

## 二、必须先用第一性原理建立问题模型

每个问题都按下面的链路追踪，不能只根据截图或表面现象改 CSS：

`用户输入 → 浏览器状态 → 前端序列化 → API 请求 → 服务端校验/业务逻辑 → 数据库存储 → 重新读取 → 前端恢复 → 模板渲染 → PDF/DOCX/Markdown/JSON 导出 → 公开页面`。

对每个缺陷写清楚：

- 最小复现步骤和实际观察结果。
- 期望结果。
- 数据第一次丢失或变形的准确节点。
- 根因候选属于状态时序、URL/域名、权限、序列化、默认值、模板条件、分页、缓存、字体、错误处理还是测试遗漏中的哪一类。
- 建议修复位置、影响范围、兼容旧数据要求和回滚思路。只提出建议，不实施修复。
- 复现证据、日志、网络响应、持久化前后值和仍然存在的边界。

## 三、重点验收范围

### 1. 创建、编辑和保存

- 注册、登录、退出、邮箱验证、密码重置、会话过期和重新登录。
- 从零创建中文简历：通用、应届生、有工作经验、科研学术四种场景。
- 基本信息：姓名、求职意向、邮箱、电话、性别、年龄、博客、GitHub、政治面貌、现居地、详细地址、自定义字段。
- 教育、技能分组、实习、工作、项目、校园经历、科研、奖项、证书、个人评价、自定义章节。
- 空字段、隐藏字段、旧简历字段、旧版本数据、切换语言和刷新后的恢复。
- 防止 React/TanStack Form 异步更新造成“界面显示新值但保存了旧值”。

### 2. 照片上传链路（本次已出现真实问题，必须重点回归）

逐步验证：选择文件、裁剪、跳过裁剪、上传成功、左侧缩略图、简历预览、切换模板、刷新、退出重登、PDF、公开页面。

必须覆盖：

- `localhost`、`127.0.0.1`、生产域名之间的图片 URL。
- `/uploads/...`、`/api/uploads/...`、带查询参数的 URL。
- JPEG、PNG、WebP、透明图片、超 10MB 图片、损坏图片。
- 上传回调中 `setFieldValue` 后立即保存的时序，确认保存的是新 URL。
- `hidden`、fit、裁剪、旋转、比例、边框、阴影。
- 删除旧照片后不能误删其他用户文件。
- API 返回 200 但图片不能加载、图片响应 Content-Type、缓存和跨站资源策略。

第一性原理检查：浏览器显示的 URL、数据库保存的 URL、静态文件真实路径、图片请求响应状态必须逐一打印并互相一致。不要用“左侧输入框有地址”代替真实图片加载验证。

### 3. 模板和版式

- 15 个模板 ID 不变，首页精选模板固定，模板库分类、搜索、单双栏、密度筛选准确。
- 参考图 ③—⑬与 `template-reference-mapping.md` 的对应关系。
- 同一份 ResumeData 切换所有模板后内容、照片、隐藏状态、技能关键词不丢失。
- 中文字体、长标题、中文英文混排、长内容三页以上、无照片、无头像。
- 个人信息不重叠，技能分组按“分组标题 + 关键词行”呈现，不把每个关键词误渲染成独立大块。
- 单栏多页左右边缘一致，双栏侧栏宽度稳定，分页不截断标题和照片。
- 模板预览、编辑器预览、PDF、DOCX 使用同一份数据和明确的差异说明。

### 4. 导入、导出与公开页面

- PDF/纯文本/JSON/Reactive Resume v4 JSON 导入。
- 中文标签、带空格标签、同一行联系方式、出生日期和电话同现、技能分组、章节别名。
- 导出 PDF、DOCX、Markdown、JSON 后检查正文、照片、链接、隐藏字段和中文标点。
- JSON 回导后再次预览和导出。
- 公开分享、匿名访问、跨账号隔离、撤销公开访问。
- 禁止性别“不公开”、私人备注、隐藏字段、私有 Agent 附件出现在公开输出。

### 5. Agent、ATS、权限和并发

- Agent 批准、拒绝、撤销、过期、重复提交、真实失败和模型不可用。
- ATS 中文章节、日期、CJK 计词、职位描述匹配和深度 PDF 检查。
- 两个标签页同时编辑不同字段，检查乐观锁、合并、冲突提示和无静默覆盖。
- 会话失效时草稿恢复、过期草稿清理、损坏 localStorage、2MB 限制。
- 每个 API 检查认证、用户隔离、输入校验、速率限制、路径穿越和上传权限。

## 四、执行方式

1. 先运行已有定向测试，再运行与发现问题最接近的只读测试。不要修改文件来让测试通过。
2. 使用当前项目固定 Node/pnpm。优先使用 package filter，避免无关全量任务。
3. 若 Docker 不可用，明确记录阻塞原因，不得把接口桩测试写成真实数据库通过。
4. 真实浏览器必须验证关键流程。每个关键断言同时检查 UI、网络/响应或持久化结果。
5. 不增加或修改测试。发现缺少回归测试时，在报告中给出测试建议和伪代码/断言设计，但不要写入测试文件。
6. 不改变认证策略、数据库数据、生产配置或模板 ID。测试产生的临时用户和临时文件必须使用项目已有的可清理测试环境，并记录清理方式；不要删除用户原有数据。
7. 不上传、推送、部署、提交 Git，不调用外部模型或外部服务发送用户数据。真实浏览器中也不要提交公开分享、邮件发送或其他外部发布动作。
8. 每条结论必须标记为“已复现”“未复现”“未验证”或“环境阻塞”。推测不能写成已确认缺陷。
