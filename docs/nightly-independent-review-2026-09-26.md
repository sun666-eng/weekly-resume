# 夜间上线验收：独立复核

日期：2026-09-26。对象：当前本地工作区、GLM 的两份夜间验收报告与其证据；不是对线上部署的重新验收。

## 结论

**维持暂不上线。** 四处小修复方向基本正确，隔离环境和导出样例有实际成果，但现有材料不足以支持“所有核心流程全部通过”或“线上所有流程没有问题”。优先完成字体外部依赖、会话失效恢复和中文 ATS 三项，再对最终生产镜像做一次可重复验收。

最重要的修正：**ATS 的缺章节和日期误报，在 Node 端完整保留中文时也能复现。不能把浏览器中文提取失败当成已确定的唯一根因。**

本轮未修改业务代码，未提交、推送或部署。新增本复核、后续提示词、独立复现工具和结果。

## 一、本轮独立核验范围

已完成：

- 阅读原始 audit、review-handoff、隔离 compose，以及注册、目录、字体、保存恢复、ATS 相关实现。
- 本地 `http://127.0.0.1:3100/api/health` 返回 200，应用、数据库、存储健康。
- 重跑 locale-catalogs 与 ats-check 两个定向测试文件，18 个测试通过。
- 将原交付 PDF 用 Poppler 渲染为 PNG 并肉眼检查：这一页中文可读，未见整页字体加载失败；不能据此证明其他网络、其他模板、多页情况正常。
- 使用项目实际 PDF 提取与 ATS 引擎分析同一份 PDF，固定分析时间与 locale，保存机器可读结果。
- 检查 PDF 文本、DOCX XML、Markdown 中“不公开/undisclosed”不存在；JSON 保留 `gender: undisclosed`，这是数据往返语义，不等于公开展示泄露。
- 查验字体清单中存在 3755 个 `fonts.gstatic.com` 引用。

未独立完成：完整浏览器端到端重跑、无代理/阻断 Google 字体环境、会话失效浏览器复现、真正同时写入的双标签冲突、全部模板多页导出、真实付费 LLM、生产服务器验收。本轮没有重跑全量 typecheck/build/全量 web 测试；原报告中的这些历史结果不能当成本轮新结果。

## 二、关键发现

### R1 / 上线阻塞：中文 ATS 的规则与语言识别确有缺陷

独立命令（仓库根目录）：

```powershell
corepack pnpm --filter @reactive-resume/tooling exec tsx review-nightly-ats.mts
```

工具：`tooling/review-nightly-ats.mts`。输入：`docs/nightly-audit-evidence/exports/resume-zh.pdf`。输出：`docs/nightly-review-evidence/ats-node-review.json`。

| 项目 | 独立结果 |
| --- | --- |
| PDF 页数 | 1 |
| 直接提取字符数 / 汉字数 | 642 / 299 |
| 引擎整理后字符数 / 汉字数 | 679 / 299（整理增加空白，不是中文缺失） |
| PDF 声明语言 | zh-CN |
| 文本质量模块 isEnglish | true |
| 英文词典命中比例 | 0.2857142857142857 |
| ATS 得分 | 60 |
| 得分封顶原因 | NO_EXPERIENCE_SECTION |
| 错误识别 | 无经历、无教育、无技能、无可识别标题等 |
| 日期错误证据 | `22.09 - 2026`，共 4 个不可解析范围 |

相关实现：

- `packages/resume/src/ats-pdf/analyze/text-quality.ts`：即使语言为 zh-CN，仍可经英文词项启发式得到 isEnglish=true；`looksLatin` 的 `|| LATIN.test(fullText)` 让少量英文技术词也满足条件。
- `packages/resume/src/ats/section-aliases.ts`：章节别名以英文为主，没有覆盖本样例的中文标题。
- `packages/resume/src/ats-pdf/analyze/semantics.ts`：日期 locale 和语言判断输入不是同一套判定；传 zh-CN 不能修复英文启发式误判。
- `packages/resume/src/ats-pdf/analyze/dates.ts`：日期端点与范围匹配会把 `2022.09 - 2026.06` 匹配成尾部片段；这是日期规则问题，不能归因于汉字丢失。

不能把所有失败项都认定为误报，例如样例本身可能没有 bullet，UNTAGGED_PDF 也需另查。修复必须针对有证据的误报，不得为了高分把全部检查改为通过。浏览器端可能另有提取问题，但尚需阶段性原文证据。

### R2 / 上线阻塞：字体外部依赖未闭环，但原风险断言过强

3755 是字体目录中的 URL 引用数量，不是一次渲染会发出的请求数量。实际字体源仍可经 `packages/fonts/src/index.ts` 的 `getWebFontSource` 进入注册/渲染链路，因此依赖风险真实存在。

原报告没有在 Google 域名不可达、缓存为空时实测，不能断言“中国大陆所有用户、所有预览/导出都会整体失败”。应在浏览器和渲染服务两侧分别阻断 `fonts.gstatic.com` / `fonts.googleapis.com`，确认具体受影响路径，再对产品实际提供的字体做同源交付和回退。不要盲目下载全部字体或只替换 CDN 域名。

### R3 / 上线阻塞：会话失效恢复需修，但不是完全没有保护

`apps/web/src/features/resume/builder/draft.ts` 已经有保存失败 toast、内存 pending 草稿、离页保存阻断和 beforeunload 相关保护。应追踪鉴权失效、路由跳转、组件卸载/清理的实际顺序，定位绕过点。

若依照原报告复现会话失效时丢失最后编辑，这是用户内容损失，应列入发布门槛。恢复设计必须区分用户和简历，防止切账号后恢复到别人名下，也不能重登录后直接覆盖服务端更新。存储不可用和服务端版本冲突需有清晰行为。

### R4 / 验收缺口：18 个测试不直接覆盖四处小修复

- 数字占位符的四处翻译方向正确，Warning 引号修复合理。
- 姓名 minLength 3 改 2 与两字中文名需求一致，错误消息接入翻译，邮箱小写转换保留。
- 现有 18 个测试没有直接断言四条数字翻译、新姓名边界等所有本次行为。
- 截图 `21 项检查中，21 项已通过` 的两数相同，无法证明位置互换已修好。要用 3/8、0/5 等不相等样例。
- 姓名空白、trim、最大长度错误、用户名和邮箱边界应补验证；不要把这些尚未实测的边界直接写成已发现的新增线上缺陷。

此外，原导出 DOCX 中仍出现 `Grade:`。这是值得补查的中文成品文案问题，不应和内容丢失类阻塞混为一谈。

### R5 / 验收缺口：交替同步不等于并发安全

当前保存链路发送完整 ResumeData。两标签轮流编辑且收到实时更新，只证明该时序能同步；不能证明同时基于旧版本修改不同字段不会相互覆盖。

下一轮要用延迟请求控制两个保存的到达顺序，同时编辑同字段和不同字段，检查最终服务端状态、两侧 UI、草稿恢复和提示。是否确实存在覆盖缺陷须通过该实验证明。

### R6 / 验收范围和可复现性需收紧

- 原证据可见 11 张截图、4 份导出样例；数量与摘要的 9 张不同，这是文档整理问题。
- 单页样例和若干模板切换不能代替全部可选模板的 2–3 页分页矩阵。
- 镜像 tag、时间和健康状态不足以证明包含所有当前脏工作区变更，最终报告应记录源码快照标识/补丁摘要与镜像 ID。
- Mock LLM 的成功只能覆盖测试替身所触发的路径。需核验其工具结果后的终止行为，补重复调用、无效参数、流中断和超时；不能推广成真实模型服务已验收。
- 可重复的 E2E 脚本和关键断言比继续积累“人工成功”文字更有价值。

## 三、可接受的原报告结论

- 隔离环境验收方式合理，Mailpit 避免向真实收件人发送测试邮件。
- 四个小修复的代码变化确实存在，建议补直接回归后保留。
- 本样例 PDF、DOCX、Markdown 没有输出“不公开”；JSON 保留原枚举值是合理往返设计。
- 岗位检索入口是重定向；未找到 `knowledge/china-job-rules` 的运行时引用。不能把规则文件或 ATS 的 JD 词项匹配宣传为现有岗位检索服务。
- 当前不适合推送到服务器直接验收，应继续在隔离的本地生产镜像上收敛阻塞项。
