# 中国岗位规则库

面向中国大陆求职场景的简历优化知识库。内容可供人工审核、规则引擎和 Agent/RAG 检索使用。

## 当前版本

- 版本：`0.1.0`
- 复核日期：`2026-09-20`
- 规则：54 条
- 岗位画像：10 个
- 数据来源：政府部门、国家公共就业服务平台、国家大学生就业服务平台
- 未采集：招聘平台登录内容、求职者简历、手机号、邮箱、照片、聊天记录

## 文件

| 文件 | 用途 |
| --- | --- |
| `rules.jsonl` | 每行一条可独立检索的简历规则 |
| `roles.json` | 岗位技能画像、简历模块顺序和证据偏好 |
| `sources.json` | 来源、授权边界和复核日期 |
| `schema.json` | JSON Schema，约束规则和岗位画像结构 |
| `validate.mjs` | 本地完整性检查，不访问网络 |

## 数据分级

- `official_guidance`：官方就业指导内容的结构化转述。
- `official_law`：法律和监管要求，不替代专业法律意见。
- `official_standard`：国家职业分类或职业标准。
- `curated_practice`：结合中国招聘习惯整理的初始基线，应由招聘专家或真实 JD 数据复核。

Agent 使用时，优先级依次为：用户事实与明确要求 > 目标 JD > 法律和隐私规则 > 官方指导 > 岗位基线。

## 推荐检索方式

1. 先按 `hardConstraint=true` 读取全部硬约束。
2. 根据用户身份筛选 `audiences`，例如 `campus`、`experienced`、`career_switcher`。
3. 根据简历模块筛选 `section`，例如 `experience`、`projects`、`education`。
4. 根据目标岗位读取 `roles.json` 中对应画像。
5. 向模型提供 5～8 条最相关规则，避免一次塞入整个知识库。
6. 输出修改时保留 `ruleId`，便于解释修改依据和收集接受/拒绝反馈。

## 使用边界

- 不根据性别、年龄、民族、婚育、籍贯等属性推断候选人能力。
- 不编造公司、项目、技术、指标、奖项、证书或工作成果。
- 用户未提供量化结果时，Agent 应提问或保留定性描述。
- 岗位画像仅用于组织证据和关键词，不代表用人单位统一标准。
- 招聘平台或企业 JD 的实时数据只能通过授权接口、允许采集的公开页面或用户主动粘贴获得。
